# Пользовательские сценарии приёмки

## Чистая установка в n8n 2.37.7

**Действие:** установить опубликованный пакет через `Settings → Community Nodes`, перезапустить n8n и открыть список нод.

**Результат:** доступны `Max`, `Max API` и `Max Trigger`; загрузка пакета не завершается ошибкой импорта `NodeConnectionType` или `form-data`.

## Совместимость существующей ноды Max

**Действие:** открыть существующий workflow с `Max`, отправить текстовое сообщение и сообщение с вложением, затем выполнить `Edit Message`.

**Результат:** сохранённые параметры открываются без миграции, запросы выполняются через `platform-api2.max.ru`, а сохранённый старый официальный host заменяется автоматически.

## Миграция ID в Max Trigger

**Действие:** активировать существующий `Max Trigger`, получить событие с небольшими и большими `user_id`/`chat_id`, затем проверить IF, Switch и Code nodes после триггера.

**Результат:** все поля `id`, `*_id` и элементы `ids`/`*_ids` приходят строками без потери точности; сравнения со строками проходят, строгие сравнения с числами требуют обновления workflow.

## Расширенные операции Max API

**Действие:** через `Max API` получить данные бота, отправить и прочитать сообщение, изменить чат, получить участников, назначить администратора, создать комментарий и webhook-подписку.

**Результат:** каждая операция использует документированный HTTP method/path, передаёт токен в `Authorization`, сохраняет ID строками и возвращает ошибку MAX как `NodeApiError`.

## Новые webhook-события

**Действие:** подписать `Max Trigger` на `bot_stopped`, `dialog_*` и `comment_*`, затем отправить валидное и повреждённое webhook-событие.

**Результат:** валидное событие запускает workflow с нормализованным `event_context`; повреждённое событие не роняет trigger execution.
