# Пользовательские сценарии приёмки

## Чистая установка в n8n 2.37.7

**Действие:** установить опубликованный пакет через `Settings → Community Nodes`, перезапустить n8n и открыть список нод.

**Результат:** доступны восемь функциональных нод `Max Bot`, `Max Chat`, `Max Chat Administrator`, `Max Chat Member`, `Max Comment`, `Max Message`, `Max Video`, `Max Subscription` и входная нода `Max Trigger`; универсальные `Max` и `Max API` отсутствуют.

## Миграция универсальных нод

**Действие:** открыть workflow версии 0.2.x с `Max` или `Max API`, зафиксировать старые параметры и заменить каждую универсальную ноду функциональной по таблице из README.

**Результат:** старая нода до замены не загружается; после ручного переноса параметров workflow выполняет ту же операцию через соответствующую функциональную ноду.

## Миграция ID в Max Trigger

**Действие:** активировать существующий `Max Trigger`, получить событие с небольшими и большими `user_id`/`chat_id`, затем проверить IF, Switch и Code nodes после триггера.

**Результат:** все поля `id`, `*_id` и элементы `ids`/`*_ids` приходят строками без потери точности; сравнения со строками проходят, строгие сравнения с числами требуют обновления workflow.

## Функциональные операции MAX API

**Действие:** через соответствующие функциональные ноды получить данные бота, отправить и прочитать сообщение, получить видео, изменить чат, получить участников, назначить администратора, создать комментарий и webhook-подписку.

**Результат:** каждая операция использует документированный HTTP method/path, передаёт токен в `Authorization`, сохраняет большие ID без округления и возвращает ошибку MAX как `NodeApiError`. В прежних операциях сообщений и чатов безопасные числовые ID остаются числами; остальные операции возвращают ID строками.

## Проверка SSL-сертификата MAX

**Действие:** при недоверенном сертификате MAX API и корректном HTTPS-адресе вебхука проверить credentials и выполнить запрос MAX, загрузку вложения и активацию `Max Trigger` сначала с выключенной, затем с включённой опцией `Ignore SSL Issues (Insecure)`. Отдельно попробовать скачать вложение с внешнего URL с недоверенным сертификатом.

**Результат:** без опции запросы MAX отклоняют сертификат; с явно включённой опцией проверка пропускается только для запросов с этими credentials, включая оба этапа загрузки и управление подпиской. Скачивание с внешнего URL и другие credentials по-прежнему проверяют сертификат; автоматического отключения проверки нет.

## Новые webhook-события

**Действие:** подписать `Max Trigger` на `bot_stopped`, `dialog_*` и `comment_*`, затем отправить валидное и повреждённое webhook-событие.

**Результат:** валидное событие запускает workflow с нормализованным `event_context`; повреждённое событие не роняет trigger execution.

## Проверка Webhook Secret

**Действие:** задать `Webhook Secret`, деактивировать и снова активировать workflow. Отправить одинаковое webhook-событие с точным `X-Max-Bot-Api-Secret`, без заголовка, с неверным значением и с несколькими значениями. Повторить проверку без настроенного секрета.

**Результат:** с настроенным секретом только точное совпадение допускает событие к обычной обработке; остальные запросы получают HTTP 403 и не запускают workflow. Пробелы по краям настройки секрета удаляются, в полученном значении заголовка — нет. Без секрета сохраняется прежняя обработка.

## ID получателя и события

**Действие:** передать в `Max Message` большой ID как число и как точную строку. Дважды обработать одно webhook-событие с тем же timestamp, затем другое сообщение.

**Результат:** небезопасное число отклоняется до HTTP-запроса; строковый ID передаётся без округления. Повтор одного события сохраняет `event_id`, другое сообщение получает другой ID.

## Неуспешный ответ подписки

**Действие:** вернуть из синтетического MAX endpoint HTTP 200 с `success: false` при создании и удалении webhook-подписки.

**Результат:** активация не сообщает об успехе; неудачное удаление возвращает `false`.

## Точность ID в ответах

**Действие:** вернуть из синтетического MAX endpoint ответ со значениями `123` и `9007199254740993` в полях ID для отправки сообщения и получения чата.

**Результат:** в этих прежних операциях `123` остаётся числом, а большой ID возвращается строкой `"9007199254740993"`; точность не теряется.
